# ChatGPT Login

本机运行的 Node 服务：邮箱验证码登录、批量任务队列、会话保存与账号管理。

## 启动

推荐使用一键启动脚本（自动检查 Node 版本、依赖与 Chromium，缺失时自动安装）：

```bash
./start.sh          # 后台启动，日志在 logs/app.log
./start.sh status   # 查看状态、端口、运行时长
./start.sh logs -f  # 跟踪日志
./start.sh stop     # 停止服务
```

带选项时默认前台运行：`./start.sh run --headed --port 3211`。完整用法见 `./start.sh --help`。

也可以用 npm 命令手动启动：

```bash
npm install
npx playwright install chromium
npm start
```

打开 **http://localhost:3210**。macOS 默认自动打开面板，设 `NO_AUTO_OPEN=1` 可关闭自动打开。

```bash
# 临时使用有头浏览器调试，不改配置文件
npm run start:headed

# 使用其他端口
PORT=3211 npm start

# 运行回归检查，不调用真实邮箱或 ChatGPT
npm test
```

Node 18 及以上即可，不需要构建前端。

## 面板操作

顶部导航分成四个独立页面：**账号概览**查看卡片、筛选与批量操作；**账号管理**新增和导入登录资料；**任务队列**查看当前任务、等待列表与本次日志；**全局设置**管理代理和界面外观。切换页面保留筛选、勾选和未保存的表单草稿，地址栏支持直接进入 `#accounts`、`#manage`、`#tasks`、`#settings`。

- **全局代理**：进入「全局设置 → 全局代理」，填写 `IP:端口`、`http://IP:端口`、`https://IP:端口` 或 `socks5://IP:端口`，可填写 HTTP(S) 认证账号和密码，勾选启用并保存。登录、取件、密码 / 2FA 操作、套餐查询统一使用该代理。运行中的账号保持原连接，新配置从下一个账号任务开始生效，无需重启；关闭后后续任务不使用应用代理。支持内嵌认证地址，但保存后会把认证信息与地址分开。
- **检测出口 IP**：使用当前表单中的代理请求 [ipify 的 IPv4 / IPv6 出口接口](https://www.ipify.org/)，显示出口 IP 与请求耗时；检测不保存草稿，也不会登录任何账号。检测失败不会回退为无代理连接。SOCKS5 使用无认证代理，HTTP(S) 可使用账号密码，符合 [Playwright 的代理支持范围](https://playwright.dev/docs/network#http-proxy)。
- **管理账号**：使用紧凑列表，每页 25 个账号，只显示邮箱及取件地址、密码、2FA 密钥的「有 / 无」状态；不在列表中显示取件凭据、密码或密钥原文。可以搜索并筛选待保存或新增账号，行内提供编辑和移除。
- **新增与编辑**：点击新增或编辑，在侧边四字段表单中填写资料，点击「应用到列表」形成草稿，再用「保存全部更改」统一保存所有页。取消表单不会改变列表，新增取消不会留下空账号；密码和密钥留空保留原记录，编辑邮箱会重新匹配对应的本机凭据状态。移除可以撤销，翻页和返回概览保留草稿，保存仍校验账号版本以避免覆盖并发修改。
- **批量导入**：粘贴 `邮箱----取件地址` 或 `邮箱----取件地址----2FA密钥`，点击「导入到列表」后检查配置状态，再保存更改。相同邮箱合并更新，其他账号保留。第三段为 Base32 密钥而非 6 位验证码；兼容 `+1` 标签、多种换行与 `#` 注释。
- **导出账号**：账号「更多 → 导出账号」下载单个账号；顶部「批量操作 → 批量导出账号」导出当前筛选结果的所有页，勾选后「更多批量操作 → 导出所选账号」只导出已选账号。下载 UTF-8 TXT，每个账号一行，格式为 `邮箱----密码----2fa----取邮件地址`，缺失字段填 `x`。使用本机当前保存的密码与 Base32 密钥，尚未登录的导入密钥也可导出；待确认新密码或更换中的新密钥通过原有单独复制入口读取。导出不运行账号任务、不修改原记录。

- **查找账号**：搜索和会员类别筛选放在账号页工具栏，支持邮箱关键词或粘贴多个邮箱（换行、空格、逗号分隔，匹配任一项）；保留 `+1` 等邮箱标签。按 `/` 聚焦搜索。类别筛选可叠加会话状态，当前筛选以可单独移除的标签显示，切换筛选返回第一页。
- **账号卡牌**：每页可选 12 / 24 / 48 张，宽屏四列，随窗口宽度依次切为三列、两列、单列。卡片统一使用 12px 内边距与间距，表单输入框高 32px。卡片直接提供登录、编辑、复制 Token 和日志；修改密码、2FA 等放在「更多」菜单。点击邮箱或套餐打开侧边详情，会员与额度、日志独立切换，关闭后仍在原页与原位置。
- **批量选择**：「选择当前页」仅选择本页，「选择匹配的 N 个」覆盖当前筛选的所有页。翻页、搜索或实时状态更新都保留已经勾选的账号；批量栏明确显示不在当前筛选中的已选数量。批量栏的操作处理已选账号，顶部「批量操作」处理当前筛选，登录和会员查询任务跳过执行中的账号；导出读取所选账号当前保存的资料。
- **删除与不可用标记**：概览页账号「更多 → 账号管理」提供「删除账号」「标记为不可用」。点击后先弹出包含邮箱和影响说明的二次确认，取消不会改动。删除从本机列表移除该账号，保留密码、2FA 密钥、会话及会员记录，重新导入同一邮箱可恢复。不可用标记保存在本机，重启和重新导入后继续生效；账号保持可编辑、可导出，登录、改密、2FA 和会员查询任务会跳过。使用「不可用」筛选定位账号，再点击「恢复使用」并确认即可恢复任务操作。正在执行或等待任务的账号需完成任务后再删除或改标记。
- **快速编辑**：点击卡片「编辑」即可在侧边修改该账号的取件地址、当前密码和 2FA 密钥，不需要跳转到完整管理页。密码和密钥默认留空，保存时保留原值；邮箱变更仍在账号管理页处理。已有未保存批量草稿时定位到管理页，防止两处草稿覆盖。服务端校验读取时的账号版本，有并发修改时保留输入并提示重开。
- **一键初始化**：点击单张卡片「更多 → 初始化密码 + 开通 2FA」，或勾选后「一键初始化所选」。顶部「批量操作」可处理当前筛选结果，也可选「仅初始化密码」「仅开通 2FA」。依次完成 12 位随机密码设置、验证器绑定和登录验证；已完成的步骤自动跳过，不重新生成已确认的密码或已有密钥。待确认密码优先核实，部分失败保留记录，下次从未完成的阶段继续。每个账号串行执行，单账号失败后继续后续账号。
- **搜索与筛选**：按邮箱或取件地址搜索；筛选可用会话、进行中和需处理账号，也可按状态或邮箱排序。
- **会员类别筛选**：按 Free、Plus、Pro 及具体档位等过滤，可叠加邮箱搜索与会话状态；未获取或未确认的会员类别单独归类。「清除筛选」恢复全部账号。批量登录会在每个账号登录成功后自动查询会员与额度，无需再单独批量获取。
- **Pro 档位识别**：卡牌和统计区分 Pro 100、Pro 200、Pro 500，筛选保留「Pro（全部档位）」与各具体档位。读取官网当前套餐提示及订阅权益标识，并保存识别依据；`chatgptprolite` / `chatgptpro` 已分别与官网的 Pro 100 / Pro 200 核对。明确的 Pro 500 名称或数字档位标识可识别为 Pro 500；只有泛化的 `pro`、旧会话、当地币种金额、余额或使用率时，保持「档位未确认」，有矛盾时提示核实。档位名称对应[官方 Pro 分档](https://learn.chatgpt.com/docs/pricing)，不代表折扣后的实付金额。旧记录在下次登录或点击「刷新会员与额度」后更新。

登录、密码或 2FA 验证成功后，自动读取一次会员类别、到期时间与窗口额度；多步初始化只在最后查询一次。同一账号任务内复用登录成功的页面和上下文，设置密码、2FA 时继续使用该页面，实际验证新密码或新密钥时仍建立全新会话。任务结束或取消时关闭本任务的上下文，不跨账号共享窗口。查询失败或超时保留已完成的登录与凭据验证结果，并保留上次会员记录；窗口额度未返回时标注旧记录的时间。账单、功能明细不再作为信息完整性的要求。
- **登录待处理**：只加入未保存有效 Token、且未在队列中的账号。有有效会话的账号可用单独的「重新登录」操作。
- **登录所选**：勾选账号后，批量登录所选账号。重复点击不会重复入队。
- **刷新会员与额度**：单个账号的「更多」菜单和详情侧栏提供手动刷新。使用已保存的会话读取；若遇到 401 且本机有已确认密码，重新登录一次，并复用新登录页面重试。普通登录后的自动查询失败不会再次触发登录。
- **批量获取会员权益**：顶部「批量操作 → 批量获取会员权益」读取当前筛选结果的所有页；勾选账号后可在「更多批量操作 → 获取所选会员权益」只刷新所选账号。任务串行执行，自动跳过正在运行或等待的账号，结果包含会员类别、到期时间和窗口额度。
- **查看会员与额度**：卡片显示会员日期，点击会员类别可查看完整时间。优先显示官网权益到期日期；只返回订阅周期结束时间时标为「本期结束」。官网未返回时明确显示未知，沿用旧日期时标注「上次记录」。点击卡片上的会员类别或窗口额度，查看主要窗口、每周窗口及代码审查窗口（以官网实际返回为准）的已用百分比与重置时间。未返回的窗口不臆造额度，时间按浏览器本机时区显示。
- **清空等待队列**：移除尚未开始的任务，当前登录继续完成。
- **复制**：直接复制 accessToken、完整 Session、邮箱、取件地址和日志。没有对应数据时按钮禁用。
- **初始化密码 / 修改密码**：在账号「操作」菜单进入官网安全设置，按官网要求完成邮箱或验证器验证，设置并记录 **12 位随机密码**，随后使用新密码完成全新登录。包含大小写字母、数字和符号，使用系统加密随机数。成功后可「复制密码」。
- **启用 2FA**：使用当前密码或取件地址登录，绑定 Google Authenticator 兼容的验证器。直接读取官网的手动 Base32 密钥，不下载、截图或保存二维码；密钥独立记录在 `twofa.json`。
- **修改 2FA**：先保存当前密钥，在官网关闭旧验证器并重新绑定新密钥。新密钥提交前保存为待确认记录，只有实际通过新密钥的验证器挑战、核对登录邮箱后才替换当前记录。中断后可「继续修改 2FA」「验证 2FA 登录」或「复制待确认 2FA 密钥」；旧密钥仍保留供恢复核对。官网已关闭验证器时继续绑定，已启用新绑定时先验证，不重复关闭。
- **2FA 验证码与登录**：可复制密钥、复制当前 6 位验证码，或运行「验证 2FA 登录」。验证使用不带旧会话的浏览器，实际通过验证器挑战并取得匹配邮箱的 Session 后才标记成功。启用后，普通登录和密码验证也会处理验证器验证码。
- **查看日志**：点击卡片「日志」打开侧边详情，或进入「任务队列」集中查看当前任务和本次运行记录；阅读旧日志时，新日志不会把位置强制拉到底部。
- **界面外观**：跟随系统、浅色或深色；支持手机布局。

账号列表修改立即同步到打开的面板。队列运行期间禁止覆盖账号列表，防止运行中途丢失账号。移除账号只更新列表，保留已保存的会话；重新导入同一邮箱时可恢复。

会员查询只读官网信息，不修改订阅。页面展示会员类别、到期时间和 Codex 窗口额度；订阅接口及官网当前套餐提示仍用于辅助识别 Pro 档位，不推算价格或 ChatGPT 聊天次数。账号含多个工作区时，以当前会话工作区为准，无法确认归属的数据不混入。查询失败保留上次成功结果、查询时间及错误。

密码任务与登录共用队列，不会同时操作同一个账号。密码独立保存在 `passwords.json`，文件权限为 `0600`，刷新 Token 或重启不会覆盖密码。密码元数据仅包含状态；按当前要求，运行日志会记录生成及验证使用的密码，点击「复制密码」也可读取。

官网目前要求至少 12 位。程序同时读取 HTML 限制及 aria-describedby 密码规则，要求变化时会显示具体错误。验证器、短信等额外验证、或已有密码但本机没有旧密码时，需要先在官网处理。

提交前先保存候选密码，随后在不带旧会话的浏览器上下文中使用新密码登录；如有附加邮箱验证码会自动取件，取得匹配邮箱的有效 Session 后才标记验证成功。如果提交后断网或进程退出，面板提供「复制待确认密码」和「验证密码登录」，并暂停再次修改，防止覆盖可能已经生效的密码；这不表示网站已接受该密码。已确认密码保存在 `password`，待确认值为 `pendingPassword`，可在核实后处理记录。

2FA 使用标准 TOTP（HMAC-SHA-1、6 位、30 秒）。临近过期时自动等待新窗口再提交。密钥写入权限为 `0600` 的 `twofa.json`，不放进列表、实时事件或日志；点击复制时按需读取。绑定失败时保留候选密钥；更换失败会记录中断阶段，重新点击修改可继续。已有验证器但本机缺少密钥时会停止，避免使原验证器失效。

导入示例（密钥仅为格式示例）：

```text
alice+1@example.com----https://mail.example.com/inbox/alice----BH4OWU3OMXPJ7P63
bob@example.com----https://mail.example.com/inbox/bob
```

面板表单保存时，密码和密钥分别存入 `passwords.json`、`twofa.json`，`accounts.txt` 只保留邮箱和取件地址。直接使用旧文本接口或编辑文件时仍兼容三段格式，登录前先保存导入的密钥；官网更换密钥前会移除该账号的旧密钥导入列，避免重启冲突。“已保存”和“已验证”分别记录，复用旧会话不会误标为已通过 2FA。没有本地密码时，邮箱验证码登录也支持随后出现的验证器挑战。重复导入相同密钥保留原验证记录；与已有密钥冲突时明确报错。以后改回两段格式不会删除已保存的密钥。

面板保留[在线验证码工具](https://2fa.dollar.xn--fiqs8s/totp-generator)入口，可将复制的 Base32 密钥粘贴进去核对。项目日常登录直接在本机计算验证码，不依赖第三方网站。

## 登录与取件

1. 有当前密码或已提交的待确认密码时，使用密码全新登录；若官网要求验证器则使用已保存的 2FA 密钥。
2. 无密码时可复用有效会话；无有效会话则通过取件地址获取邮箱验证码，再按需完成 2FA。显式「验证 2FA 登录」始终跳过旧会话，并要求实际出现验证器挑战。只有密钥、没有密码或取件地址时提示补充资料。
3. **提交邮箱前**打开取件箱，记录历史邮件的稳定 ID；在实际提交邮箱或触发验证码前记录请求时间。只读取 ID 未见过、邮件时间属于本次请求的邮件，按时间从新到旧选择。
4. 新邮件已送达但正文尚未加载时继续轮询，避免提前排除其 ID。网络取件失败会在等待期限内重试。
5. 验证失败时，重发前重新记录现有邮件，并更新发信时间起点，再等待新验证码。验证码不会明文写入日志。
6. 现有新账号信息页流程保留，填写失败会明确报错，不再吞掉异常后假报成功。
7. 成功后原样保存 Session 的 `raw` 字符串，同时提取 `accessToken`。浏览器状态与会话库采用临时文件写入后替换。

时间比较读取 `<time datetime>` 中带时区的原始时间戳，不把页面显示的北京时间当作 UTC。邮件时间精度为秒，同一秒内用提交前的 ID 基线补充判断；缺失或无法解析时间的邮件不用于登录。取件箱当前适配含 `article`、`data-message-id`、`button.message-row` 的页面。

同时支持 `https://api.wdmail.top/m?f=html&e=邮箱:取件凭据`：读取每封邮件的标题、收件人和时间，从 `iframe srcdoc` 提取完整正文，兼容页面隐藏邮箱地址的编码。该服务未标注时区的时间按北京时间（UTC+08:00）处理；邮件正文中的样式、脚本不参与验证码匹配。继续使用邮件 ID 基线和本次发信时间排除旧码，兼容 iCloud 的 `+1` 等别名；取件地址里的凭据原样保留。

登录和保存账号时保留完整的 `+1` 等邮箱标签。取件箱若把 iCloud 别名的收件人显示为基础邮箱，允许匹配该基础邮箱，但仍要求邮件 ID 与实际时间均属于本次请求；不会把明确标为 `+2` 的邮件当成 `+1`。

每个账号都有独立浏览器上下文。单账号超过总超时限制会关闭其上下文并继续后续账号。服务退出会清空等待队列、停止当前任务并关闭浏览器。

## 配置

`config.json` 示例：

```json
{
  "port": 3210,
  "mail": {
    "url": "",
    "pageLoadWaitMs": 2000,
    "pollIntervalMs": 4000,
    "maxWaitMs": 120000
  },
  "batch": {
    "headless": true,
    "delayBetweenAccountsMs": 3000,
    "perAccountTimeoutMs": 300000,
    "openRetry": 3,
    "openTimeoutMs": 45000
  }
}
```

修改配置后重启服务。`perAccountTimeoutMs` 覆盖单账号的整个执行过程，包括页面重试和等待验证码；不包含排队时间。「初始化密码 + 开通 2FA」及「修改 2FA」预留两倍时间，其余任务使用原配置。`HEADLESS_OVERRIDE=0` 或 `1` 可临时覆盖浏览器模式。

代理配置通过面板保存到独立的 `proxy.json`（权限 `0600`），不修改 `config.json` 或系统代理。代理密码不随配置接口及实时事件返回；密码留空只保留同一代理地址、同一认证账号的已存密码，切换地址或账号时需重新填写密码。可以勾选「清除已保存的代理密码」。未配置时默认不启用应用代理。

`info.json` 中每个邮箱对应：

```json
{
  "email": "alice@example.com",
  "accessToken": "...",
  "raw": "{\"accessToken\":\"...\",\"user\":{...},\"expires\":\"...\"}",
  "expires": "2027-01-11T00:00:00.000Z",
  "fetchedAt": "2026-10-13T00:00:00.000Z"
}
```

重启后恢复未过期会话的可用状态。有效期取 accessToken 的 JWT `exp` 和 Session `expires` 中较早的时间；无法读取 JWT 时使用 Session 有效期。面板的「可用」表示已保存且未过期，实际是否被撤销需要重新登录校验。JWT 只用于读取过期信息，不作为签名验证。API 的 `tokenExpires` 是动态计算的字段，不改写原 Session。损坏的会话库会阻止启动并保留原文件，避免覆盖原有数据。

服务仅监听 `127.0.0.1`，API 仅接受本机地址和同源面板访问。新写入的账号、会话和浏览器状态文件权限为 `0600`。`info.json`、`profiles/` 和取件地址包含登录凭据，应留在本机；相关文件已被 `.gitignore` 排除。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/accounts` | 当前账号与最多 300 行日志 |
| POST | `/api/plans/refresh` | `{}` 查询全部账号；`{ "emails": [...] }` 查询所选账号，返回实际入队数量；结果通过账号列表的 `plan` 字段及 SSE 更新 |
| POST | `/api/login` | `{ "email": "..." }` |
| POST | `/api/login-batch` | `{ "emails": [...] }`；返回实际入队数量 |
| POST | `/api/password/init` | `{ "email": "..." }`；初始化或重新生成 12 位密码，返回实际入队数量 |
| POST | `/api/password/change` | `{ "email": "..." }`；到官网更换为 12 位随机密码，与初始化共用验证及候选保护流程 |
| POST | `/api/password/verify` | `{ "email": "..." }`；优先验证待确认密码，否则验证已记录密码，成功后更新会话 |
| GET | `/api/password?email=...` | 读取已确认密码；`pending=1` 读取提交结果待确认的候选密码 |
| POST | `/api/twofa/init` | `{ "email": "..." }`；绑定验证器并完成密码或邮箱验证码 + TOTP 登录验证 |
| POST | `/api/twofa/replace` | `{ "email": "..." }`；在官网更换验证器并验证新密钥，已有未完成任务时恢复该流程 |
| POST | `/api/twofa/verify` | `{ "email": "..." }`；用已保存的密钥验证完整登录 |
| GET | `/api/twofa?email=...` | 按需读取 `secret`、当前 `code`、`remaining` 秒和 `expiresAt`；`pending=1` 读取更换中的待确认新密钥 |
| POST | `/api/queue/clear` | 清空等待任务，返回 `cleared` |
| GET | `/api/events` | 每次连接先推完整快照，随后推状态、日志、列表与队列更新；15 秒心跳 |
| GET / POST | `/api/accounts-file` | 读取 `content` 与结构化 `accounts`；提交 `{ "accounts": [{ "email": "...", "mailUrl": "...", "password": "...", "totpSecret": "..." }] }` 保存当前登录资料；密码、密钥留空保留，不随列表回显。仍兼容 `{ "content": "..." }` |
| POST | `/api/accounts/parse` | `{ "content": "..." }` 校验并解析导入文本，返回 `accounts`，不写入文件 |
| POST | `/api/accounts/export` | `{ "emails": [...] }` 按指定顺序去重导出已保存账号，返回 `{ "content": "...", "count": N }`；四字段以 `----` 分隔、账号以换行分隔，缺失值为 `x`；仅读取、不排队或写入 |
| POST | `/api/accounts/action` | `{ "email": "...", "action": "delete" / "disable" / "restore", "confirmed": true }` 二次确认后移除本机列表项或设置可用标记；拒绝操作正在执行或等待任务的账号，返回更新后的 `accounts` |
| POST | `/api/accounts/setup` | `{ "emails": [...], "mode": "all" }` 一键初始化；`mode` 可为 `password` / `twofa`，返回实际 `queued` 和 `skipped` 数量 |
| GET | `/api/worker` | `queue`、`inFlight`、`running` |
| GET | `/api/config` | 当前生效配置 |
| GET / POST | `/api/proxy` | 读取或保存 `{ "enabled": true, "server": "http://127.0.0.1:7890", "username": "", "password": "" }`；读取返回 `hasPassword`，不返回密码；`clearPassword: true` 清除已存密码 |
| POST | `/api/proxy/test` | 使用同样格式的草稿配置检测出口 IP，返回 `ip`、`latencyMs`、`checkedAt`，不保存配置、不运行账号任务 |

错误返回 JSON，非法参数 `400`、跨源访问 `403`、方法不支持 `405`、运行期间覆盖账号 `409`、超过 1 MB 的请求体 `413`。登录请求成功返回 `202`；已经在队列中的账号不重复计数。

回归检查使用临时文件、模拟取件页面和模拟登录任务，不触发真实批量登录。
